## Diagnosis (root causes found, not just symptoms)
1. **Idle CPU/heat drivers**
   - `HomeFragment.shizukuPoller` ran every 2 s and spawned a fresh `Thread` per tick →
     `ShizukuShell.state()` → `PackageManager.getPackageInfo` IPC + `pingBinder()` + possible
     blocking `ensureBound` (≤2.5 s) **every tick**, no single-flight → thread pile-up.
   - `ShizukuShell.isUsable()` answered by executing shell `run("true")` (2 s cache), called from
     `AndroidExecutor.privileged` → idle shell executions.
   - `MonitorHub` sampled at a fixed 1 s whenever the UI was the monitor client
     (`MainActivity.onResume` sets client UI), including 10 s TCP ping + retrans reads.
2. **"Dead" UI elements — common cause**
   - Listeners are attached with nullable `?.setOnClickListener`; if a view id is missing from the
     inflated layout the listener is silently skipped → button does nothing with no error.
   - `onShizukuAction` spawned a blocking thread per tap with no in-flight guard and a silent
     `activity ?: return` → taps during an operation looked dead.
   - No `SESSION_EXPIRED` state and no immediate binder-dead notification: `run()` silently
     unbound, so the UI kept showing a stale state until the next poll.
   - Command results were never surfaced (sent ≠ executed), and `isUsable` used a shell round-trip.

## Changes (before → after)
| Area | Before | After |
|---|---|---|
| Shizuku poller | new Thread every 2 s, unbounded, getPackageInfo IPC each tick | single-flight `AtomicBoolean`; adaptive 2 s (not ready / card visible) → 15 s backstop; installed check cached 30 s |
| Shizuku state → UI | 5 legacy states, no binder-dead notify, card hidden when ready | pure resolver `core/ShizukuConnection.kt` (DISCONNECTED / CONNECTED_NO_PERMISSION / CONNECTED_GRANTED / SESSION_EXPIRED) + global Shizuku listeners → immediate main-thread notify; card always visible |
| Command outcome | not tracked | `CommandStatus` IDLE/RUNNING/SUCCEEDED/FAILED set from the **real exit code**; shown on the card + real permission grant/deny |
| Shizuku button tap | blocking thread per tap, no guard | in-flight guard + "Working…" label + post-action refresh |
| Missing-view bug | silent `?.` skip | `auditViewWiring` logs any missing critical id to the session log |
| Monitor loop | fixed 1 s, ping+retrans always | `IdlePolicy.monitorIntervalMs`: 1 s (session/overlay) / 5 s (UI only) / stop when idle; `networkProbeAllowed` gates ping/retrans at idle |
| Usability check | shell `true` round-trip | `IdlePolicy.usableWithoutCommand(binderAlive, bound)`; command check opt-in `verifyWithCommand` |
| UI text updates | every snapshot re-sets text | `setTextIfChanged` skips unchanged values; thermal-guard status line added |

**Untouched on purpose (RULE-04/05 + user constraint):** the boost engine, session journal,
restore/retry logic, task set, `ThermalGuard` limits (never raised, never bypassed), Shizuku/Root
features, FPS overlay behavior. The CoC performance path is byte-identical.
